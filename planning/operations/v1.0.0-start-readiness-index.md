## 2) Governance Gate Entry Points

Основной агрегатор:

```bash
bash scripts/ci/run_e2e_governance.sh --mode ci
bash scripts/ci/run_e2e_governance.sh --mode release
```

Отдельные валидаторы:

```bash
bash scripts/ci/validate_vsa_dependency_graph.sh
bash scripts/ci/validate_release_evidence_freshness.sh --mode policy
bash scripts/ci/validate_release_evidence_freshness.sh --mode strict
python3 scripts/ci/refresh_release_evidence_manifest.py
```

## 3) Обязательные проверки перед release decision

1. `bash planning/system/validate_planning.sh`
2. `python3 scripts/ci/refresh_release_evidence_manifest.py`
3. `bash scripts/ci/run_e2e_governance.sh --mode release`
4. Runtime quality commands:
  - `cargo check --workspace --locked`
  - `cargo test --workspace --locked`
  - `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
  - `cargo fmt --all -- --check`
5. Security gates:
  - `cargo deny check bans licenses advisories sources`
  - `cargo audit`
6. Compatibility gate:
  - `bash scripts/mvp/run_matrix.sh 3`

## 5) Статусная политика

- Этот индекс задает правила readiness и обязательные команды, но не фиксирует pass/fail конкретного запуска.
- Датированные формулировки вида "run verified" считаются неавторитетными без manifest anchor и строгой валидации.
- Перед strict validation manifest должен быть обновлен под выбранный release-preparation `HEAD` через `python3 scripts/ci/refresh_release_evidence_manifest.py` или его preview-вариант с `--output`.
- Фактический статус конкретного запуска подтверждается только логами команд и выводом strict governance validation.
