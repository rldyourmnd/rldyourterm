# v1.0.0 Manual Test Plan (MVP closure sync)

Manual-only validation harness for v1.0 MVP closure readiness.

Req coverage in this plan:
- `R-11`: single-window baseline is mandatory and evidence-backed.
- `R-12`: release governance remains manual-only with explicit proof artifacts.
- `R-13`: Claude/Codex/Gemini compatibility is a release-blocking gate.

## 0. Evidence Flow (Authoritative)

1. Execute policy/governance preflight before collecting release evidence:
  - `bash planning/system/validate_planning.sh`
  - `bash scripts/ci/validate_vsa_dependency_graph.sh`
  - `bash scripts/ci/validate_release_evidence_freshness.sh --mode policy`
2. Execute profile or matrix commands from `scripts/mvp/*`.
2. Capture terminal transcript for gate outputs:
  - `MVP_PROFILE_START ...`
  - `MVP_GATE_RESULT ... status=pass ...`
  - `MVP_MATRIX_RESULT ... status=pass ...`
3. Collect profile logs generated by `run_profile.sh` in `scripts/mvp/output/*.log`:
  - `MVP_HARNESS ... single_window_required=1 release_governance=manual-only`
  - `repo_head_sha=<selected HEAD>`
  - `MVP_HARNESS_CMD ... --window-count 1 ...`
  - `MVP_STEP ... command=single-window:1 ...`
  - `MVP_RESULT ...`
4. Record both artifact types and manifest anchor in the release checklist (`planning/operations/v1.0.0-release-pack.md`) and ensure the machine-readable source of truth remains:
  - `planning/operations/v1.0.0-evidence-manifest.json`
5. Refresh the manifest against the current release-preparation HEAD and latest MVP logs:
  - preferred clean-worktree preview: `python3 scripts/ci/refresh_release_evidence_manifest.py --output /tmp/rldyourterm-evidence-manifest.json`
  - optional in-repo baseline refresh: `python3 scripts/ci/refresh_release_evidence_manifest.py`
6. Before final signoff, run strict HEAD-bound governance validation:
  - `bash scripts/ci/run_e2e_governance.sh --mode release --manifest /tmp/rldyourterm-evidence-manifest.json`
  - if fresh compatibility logs must be regenerated in the same flow: append `--with-matrix` so the command runs matrix -> refresh manifest -> strict validation in one pass

Single-window invariant:
- Every harness run must use `--window-count 1`.
- Every accepted `MVP_RESULT` must contain:
  - `windows=1`
  - `single_window_required=1`
  - `single_window_enforced=yes`

Pass criteria per profile log (`scripts/mvp/output/<profile>-<timestamp>.log`):
- `MVP_HARNESS` exists with `single_window_required=1` and `release_governance=manual-only`.
- `MVP_HARNESS_CMD` exists and includes `--window-count 1`.
- `MVP_RESULT` exists.

- `state=running` or `state=degraded` is present (no crash-stop path).

Pass criteria per terminal transcript (`gate-*.log` or `matrix-*.log`):
- each scenario transcript ends with `MVP_GATE_RESULT ... status=pass ...`.
- matrix transcript ends with `MVP_MATRIX_RESULT ... status=pass ...`.
- no `MVP_GATE_RESULT ... status=fail ...` or `MVP_MATRIX_RESULT ... status=fail ...`.

## 2A. Interactive GUI Run Smoke-Check (Informational)

Purpose:
- validate direct interactive GUI runtime path outside the MVP harness.
- confirm post-wave GUI integration without changing compatibility gate ownership.

Execute:
```bash
cargo run -q -p rldyourterm-app -- --mode auto --shell fish --window-count 1
```

Verify:
- application opens a visible GUI window (single-window baseline).
- interactive session accepts input commands (for example: `echo interactive-gui-smoke`, `pwd`).
- command output is rendered inside GUI window without session drop.
- `exit` in shell (or window close) terminates the runtime cleanly (no panic/crash path).

TTY fallback verification (optional, informational):
```bash
cargo run -q -p rldyourterm-app -- --mode auto --shell fish --window-count 1 --tty
```
- confirms deterministic legacy TTY path remains available.

## 3. Stability Scenarios

1. GPU degrade without session drop
- Execute:
```bash
bash scripts/mvp/run_profile.sh codex 3 gpu-failure:surface-error:1000 gpu-failure:submit-error:1500 gpu-failure:swapchain-out-of-date:2000 tick mode:auto
```
- Verify session remains active and a valid `MVP_RESULT` is emitted.
- Verify `MVP_RESULT` includes `gpu_retry_observed=yes` and `fallback_observed=yes`.
- Verify profile transcript includes `[runtime] gpu auto-fallback ... correlation-id=` notice (no silent fallback).

2. PTY recoverable boundary handling
- Execute:
```bash
bash scripts/mvp/run_profile.sh claude 3 recoverable:pty-read tick
```
- Verify recoverable path does not terminate the runtime.

3. Startup determinism + shell fallback visibility
- Execute:
```bash
cargo run -q -p rldyourterm-app -- --mode auto --shell fish --window-count 1
```
- Verify deterministic startup completion, GUI window visibility, and fallback warning visibility when fish baseline is unavailable.

4. Forced `gpu` mode is explicit-fatal (no silent CPU fallback)
- Execute:
```bash
cargo test -q -p rldyourterm-app forced_gpu_mode_reports_explicit_gpu_failure
```
- Verify the test passes and confirms `GpuFailureHandling::FatalForcedGpu` for injected GPU failure under `RenderMode::Gpu`.

## 4. Speed and Cadence Scenarios

5. Monitor transfer cadence re-sync
- Execute:
```bash
bash scripts/mvp/run_profile.sh gemini 3 transfer-cadence:144000 transfer-cadence:60000 tick
```
- Verify cadence-change commands produce a valid final `MVP_RESULT`.
- Verify `MVP_RESULT` includes `cadence_resync_observed=yes`.
- Verify transcript contains `MVP_STEP ... command=transfer-cadence:144000` and `MVP_STEP ... command=transfer-cadence:60000`.

6. Long-run bounded behavior smoke
- Execute:
```bash
bash scripts/mvp/run_matrix.sh 5
```
- Verify repeated runs keep producing deterministic `MVP_RESULT` lines with `windows=1`.
- Verify command exit emits `MVP_MATRIX_RESULT ... status=pass ...`.

7. Scrollback dual-bound evidence (deep history + OOM guardrail)
- Execute:
```bash
cargo test -q -p rldyourterm-core stress_scrollback_cap_enforced_at_50k
cargo test -q -p rldyourterm-core byte_cap_trims_oldest_lines_when_budget_is_exceeded
cargo test -q -p rldyourterm-core oversized_line_does_not_evict_existing_history
```
- Verify all three checks pass:
  - line-cap invariant remains fixed at 50_000,
  - byte-budget eviction works deterministically,
  - oversized incoming line is rejected without evicting prior history.
