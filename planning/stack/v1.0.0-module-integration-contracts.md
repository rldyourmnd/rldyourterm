# Module Integration Contracts (v1.0.0)

## External Modules (Hard deps)

### 1. `portable-pty` — PTY lifecycle
- Назначение: spawn shell, pty IO, resize, process kill/wait.
- Внешний API используется через адаптерный интерфейс `foundation/api::pty`.
- Контракт:
  - `openpty(size) -> (master, slave)`
  - `slave.spawn_command(CommandBuilder)`
  - `master.try_clone_reader()` + `master.take_writer()`
  - `master.resize(PtySize)`
  - `Child::try_wait / wait / kill`
- Риск:
  - EIO/EOF, зависание процесса при kill.
- Контроль:
  - `SessionController` с bounded retry.
  - timeout на read-write pump.
  - PTY output delivery в GUI path обязана использовать bounded queue/backpressure между reader pump и UI event loop (без unbounded per-chunk event fanout).

### 2. `winit` — window/event loop
- Назначение: создание окна, цикл событий, клавиатура/мышь, resize, redraw.
- Контракт:
  - window create only through active event loop;
  - обработка `WindowEvent::{CloseRequested, Moved, Resized, ScaleFactorChanged, RedrawRequested, KeyboardInput, CursorMoved, MouseWheel, Focused}`.
  - определение текущего монитора через `Window::current_monitor()` и извлечение refresh-rate через `MonitorHandle::refresh_rate_millihertz()`.
  - обработка modifier keys и control flow.
- Риск:
  - разный lifecycle между Linux/Windows/macOS, дрейф DPI и несинхронный refresh-rate при переносе окна.
- Контроль:
- отдельный слой `foundation/api::window` с единым event translation.
- при изменении монитора emit события изменения cadence в services.
- viewport->terminal resize проходит через runtime safety caps (axis + total cells), чтобы исключить OOM-scale realloc при аномальных window size событиях.

### 3. `wgpu` — GPU backend
- Назначение: accelerated render path.
- Контракт:
  - запрос устройства/очереди;
  - surface config, swap chain lifecycle;
  - `RequestAdapterOptions.power_preference`: `HighPerformance` для приоритета latency/throughput в AI CLI interactive path;
  - `DeviceDescriptor.memory_hints`: `Performance` (предпочтение скорости и VRAM-friendly allocation strategy);
  - `present_mode`: предпочтительно `AutoVsync` (или гарантированный `Fifo`, если backend не поддерживает auto-режим);
  - `desired_maximum_frame_latency=1` как low-latency hint (single frame in flight), без hardcoded fps в primary pacing path.
  - буферы cell-instance допускают контролируемый `grow/shrink`: геометрический рост и shrink только после устойчивой недоиспользованности; при realloc старые GPU buffer resources освобождаются явным `Buffer::destroy()`.
  - обновления данных выполняются через `Queue::write_buffer` c `submit`-driven staging семантикой; при realloc обязателен full upload кадра, чтобы исключить partial-state corruption.
  - cell metadata (flags/fg/bg) читаются из storage buffer в vertex stage и передаются во fragment через flat-varyings; fragment path не должен выполнять повторный storage read на пиксель.
  - submit/render pass + error handling hooks.
- Риск:
  - потеря устройства, ошибки поверхности, submit error, удержание VRAM high-water после burst-нагрузки.
- Контроль:
  - `wgpu::Device::on_uncaptured_error`, device lost callback, fallback pipeline.
  - deferred GPU init в GUI runtime имеет bounded retry budget; при исчерпании в `auto` mode применяется детерминированный `gpu -> cpu` fallback через `RenderModeTransition` + user-visible notice + diagnostics correlation.
  - forced `gpu` mode не деградирует silently: при исчерпании retry бюджета deferred init завершается explicit fatal path.
  - surface errors классифицируются детерминированно (`Timeout -> retry`, `Outdated/Lost -> reconfigure`, `OutOfMemory/Other -> degrade`) с bounded retry и reset counters после успешного acquire/reconfigure.

### 4. Structured diagnostics stack (`tracing`, `tracing-subscriber`)
- Назначение: наблюдаемость GPU/PTY/UI событий, event-id, время отклика.
- Контракт:
  - span/event для: spawn, resize, input, render transition, fallback.
- Риск:
  - шумные логи/рост CPU.
- Контроль:
  - уровни INFO/DEBUG и sample rate для стабильности.

### 5. CLI/runtime (`clap`, `serde`, `dirs`, `thiserror`)
- Назначение: параметры запуска + типизированные настройки.
- Контракт:
  - `--mode`, `--shell`, `--no-gpu`, `--trace`, profile paths.
- Риск:
  - invalid argument state.
- Контроль:
  - schema validation at parse time + deterministic fallback to defaults.

### 6. UX/interop (`arboard`)
- Назначение: copy/paste на уровне OS.
- Контракт:
  - отдельный feature в `services/io`.
- Риск:
  - потеря clipboard contents при crash loop.
- Контроль:
  - retry + bounded user notifications.

### 7. `crossterm` — interactive TTY control (app runtime)
- Назначение: raw-mode input loop и terminal event ingestion для интерактивного PTY runtime (`rldyourterm-app` вне MVP harness).
- Контракт:
  - `terminal::enable_raw_mode()`/`terminal::disable_raw_mode()` через guard lifecycle;
  - `event::poll(timeout)` + `event::read()` для keyboard/resize событий;
  - `Event::Resize(cols, rows)` -> `PtyIo::resize(PtySize)` через foundation boundary.
- Риск:
  - raw mode может остаться включенным при аварийном пути;
  - input loop может вызывать jitter/latency при неверном cadence poll.
- Контроль:
  - RAII guard с гарантированным `disable_raw_mode` в `Drop`;
  - bounded poll timeout и deterministic shutdown (`Ctrl+Q`, `exit`, child-exit path);
  - ошибки resize/write переводятся в bounded degradation без panic path.

### 8. `softbuffer` + `font8x8` — GUI CPU presentation path (app runtime)
- Назначение:
  - `softbuffer`: platform-independent software frame presentation в окно `winit` без обязательной GPU зависимости.
  - `font8x8`: bitmap glyph source для минимального monospace text draw в GUI MVP path.
- Контракт:
  - `softbuffer::Context::new(window)` + `Surface::new(&context, window)` при startup GUI runtime.
  - `Surface::resize(width,height)` + `buffer_mut()` + `present()` в `RedrawRequested`.
  - PTY output байты переводятся в внутренний строковый буфер и отрисовываются CPU path.
  - это implementation detail CPU presentation path, не новый render mode (render modes остаются `cpu|gpu|auto`).
- Риск:
  - init/present failure в GUI path;
  - повреждение читаемости при ANSI-heavy output и resize burst.
- Контроль:
  - deterministic fallback: при GUI bootstrap failure переход в TTY runtime с явным warning/event;
  - bounded redraw path + single-window invariant сохраняется;
  - мониторный cadence contract остается monitor-driven через `winit` event loop.

## Internal/External Boundary
- Ни один external crate не знает внутренний формат `GridState` или event bus.
- Внешний код входит только через строго типизированные adapters and traits.
- Performance-critical runtime logic (session orchestration, parser/grid state, fallback policy, pacing policy) реализуется как project-owned code.
- External crates используются только как boundary integrations, а не как замена терминального ядра.

## Decision: Что НЕ подключаем в v1.0
- Multiplexer engine.
- Легаси full lua-плагинная модель.
- Сложные рендер-эффекты (blur/shadow) и расширенная графика.
- Необязательные Windows-only расширения.
