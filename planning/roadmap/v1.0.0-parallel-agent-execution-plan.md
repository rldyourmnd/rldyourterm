# v1.0.0 Parallel Agent Execution Plan (10 Agents, VSA Mandatory)

Date: 2026-03-02
Status: Draft for execution kickoff
Scope: MVP 1.0 implementation from planning-first reset baseline

## 1) Objective

Build MVP 1.0 terminal runtime with hard priorities:
1. Crash-intolerant stability.
2. AI CLI compatibility (`Claude Code`, `Codex`, `Gemini CLI`).
3. Ultra-low latency speed.

## 2) Hard Constraints

- VSA layering is mandatory: `app -> features -> services -> core`; platform details behind `foundation/api` adapters.
- No silent fallback.
- No hardcoded FPS in primary runtime path.
- Single-window baseline.
- Self-authored-first runtime logic.
- Manual evidence-driven release gating.

## 3) Source-backed Boundary Dependencies (Context7)

- `portable-pty` (`docs.rs/portable-pty/latest`): `openpty`, `spawn_command`, `try_clone_reader`, `take_writer` (single writer), `resize`, `try_wait/wait/kill`.
- `winit` (`docs.rs/winit/latest`): monitor/window lifecycle and monitor refresh APIs (`current_monitor`, `refresh_rate_millihertz`, redraw/window events).
- `wgpu` (`docs.rs/wgpu/latest`): `SurfaceConfiguration` (`present_mode`, `desired_maximum_frame_latency`) and `SurfaceError` (`Timeout`, `Outdated`, `Lost`, `OutOfMemory`, `Other`).

## 4) Multi-Agent Orchestration Model

### 4.1 Coordination Rules

- One integration branch per agent: `agent/<id>-<scope>`.
- Agent PRs are merged only through wave gates (defined below).
- No agent may change another agent's owned module unless explicitly marked as `shared-contract edit`.
- Every PR must include:
  - impacted `Req IDs`,
  - risk links,
  - manual test notes,
  - traceability update if interfaces changed.

### 4.2 Global Shared Contracts (frozen before coding)

- `foundation/api` traits (PTY/window/diagnostics/clipboard).
- `core` event/state envelope types.
- `services` public orchestration interfaces.
- error taxonomy (`DomainError` families + severity + correlation id fields).

## 5) 10-Agent Work Allocation

## Agent 01 — Core Engine

- Mission: implement `core` terminal model (grid, cursor, scrollback, parser baseline, dirty regions).
- Owns:
  - `crates/core/*` (new workspace)
  - core event/value types shared by services.
- Inputs:
  - VSA contracts, R-06, R-08.
- Outputs:
  - deterministic state machine,
  - bounded scrollback (50_000 cap),
  - parser degrade behavior for unsupported sequences.
- Done criteria:
  - no OS/GPU/PTY imports in core,
  - deterministic tests for parser/state transitions,
  - memory bound tests for scrollback policy.
- Risks covered: 5, 10.

## Agent 02 — Foundation PTY Adapter

- Mission: create PTY integration boundary with lifecycle-safe semantics.
- Owns:
  - `crates/foundation/api/pty.rs`
  - `crates/foundation-platform/<os>/pty/*`
- Inputs:
  - ADR-0002, R-09.
- Outputs:
  - safe open/spawn/read/write/resize/close/kill/wait contracts,
  - single-writer invariant enforcement,
  - normalized PTY error mapping.
- Done criteria:
  - `take_writer` one-time semantics enforced,
  - resize path triggers PTY kernel update,
  - blocked/hung child handling path documented + tested.
- Risks covered: 2, 6.

## Agent 03 — Foundation Window/Monitor Adapter

## 6) Dependency Graph and Parallel Waves

## Wave 0 (Contract Freeze)

- Required first: shared interfaces + error/event taxonomy freeze.
- Participants: Agents 01, 02, 03, 09 (joint contract PR).
- Exit gate:
  - interface signatures frozen,
  - traceability links updated.

## Wave 1 (Foundation + Core Parallel)

- Parallel lanes:
  - Agent 01 (core engine)
  - Agent 02 (PTY)
  - Agent 03 (window/monitor)
  - Agent 09 (diagnostics skeleton)
- Exit gate:
  - compile-level integration of contracts,
  - baseline unit tests green.

## Wave 2 (Service Control Plane)

- Parallel lanes:
  - Agent 04 (session lifecycle)
  - Agent 05 (render mode/fallback/pacing)
  - Agent 08 (settings/config)
- Dependency:
  - requires Wave 1 interfaces.
- Exit gate:
  - deterministic state transitions for session/mode/settings.

## Wave 3 (Render Data Plane)

- Parallel lanes:
  - Agent 06 (CPU renderer)
  - Agent 07 (GPU renderer)
- Dependency:
  - requires Agent 05 controller contracts.
- Exit gate:
  - `cpu/gpu/auto` end-to-end mode switching functional.

## Wave 4 (System Hardening + Evidence)

- Primary owner: Agent 10, with fixes from all agents.
- Scope:
  - AI CLI long-session runs,
  - latency/stress/failure injection evidence,
  - release checklist completion.
- Exit gate:
  - quality gates + acceptance matrix + release pack pass.

## 7) PR and Integration Protocol

- Each agent PR template must include:
  - `Req:` IDs,
  - `Risk:` IDs,
  - `Contracts touched:`,
  - `Manual test evidence:` links,
  - `Rollback strategy:`.
- Merge order follows wave order only.
- Any cross-wave contract change reopens Wave 0 for impacted interfaces.

## 8) Validation Matrix by Wave

- Wave 0: planning validation + contract lint checklist.
- Wave 1: unit tests for core/foundation adapters + event schema sanity.
- Wave 2: deterministic service state-machine tests + fallback policy tests.
- Wave 3: renderer integration tests (`cpu`, `gpu`, `auto`) + monitor transfer smoke.
- Wave 4: manual compatibility/stability/latency evidence and release gate checks.

## 9) Rollback Strategy

- If an agent lane destabilizes shared contracts:
  - revert lane branch merge,
  - restore previous contract tag,
  - reopen affected wave with narrowed scope.
- If GPU path causes instability in integration:
  - block release,
  - force runtime default to `cpu` while keeping `gpu` behind guarded flag until fixed.
- If AI CLI compatibility fails:
  - release blocked regardless of other green checks.

## 10) Definition of Ready for Launching the 10 Agents

Before parallel execution starts, must be true:
1. New workspace skeleton and crate boundaries are created.
2. Shared contract files exist and are frozen for Wave 0.
3. Agent ownership map is accepted.
4. Branch naming and PR template policy are in place.
5. Validation and evidence checklist files are pre-created.
