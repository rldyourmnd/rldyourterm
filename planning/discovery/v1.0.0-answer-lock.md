## Core Product Intent (Hard Order)

1) `СТАБИЛЬНОСТЬ`
- Crash-intolerant runtime target.
- No recoverable fault may terminate an active shell session.
- Any panic/crash is `Sev-0` and release-blocking.

2) `AI TOOL COMPATIBILITY`
- Primary compatibility targets: `Claude Code`, `Codex`, `Gemini CLI`.
- Long-running agent sessions must preserve deterministic input/output timing and session continuity.

3) `СКОРОСТЬ`
- Ultra-low interactive latency for prompt-to-paint and command round-trip.
- Bounded CPU/RAM growth under long session load.

## Locked Answers (1..22)

1) Primary user
- Product visionary + AI CLI power-user.

2) Task profile
- Mixed manual + AI automation workloads with long-lived sessions.

3) Crash/SLA policy
- Runtime must avoid crash paths; recoverable failures stay in-session.

4) Automatic fallback policy
- GPU failures trigger bounded retries and deterministic `gpu -> cpu` fallback with user-visible event.

5) Memory discipline
- Bounded growth required; scrollback keeps default cap 50_000 lines with an additional high byte-budget guardrail (default 512 MiB) to preserve long history while preventing OOM drift.

6) Frame pacing policy
- No hardcoded FPS in primary path.
- Cadence must be monitor-driven via system refresh-rate and re-sync on monitor transfer.

7) Shell baseline
- `fish + starship` baseline, `zsh` fallback, Bash non-primary on Linux/macOS.

8) ANSI/terminal behavior
- Correct baseline behavior first (cursor/colors/clear/scroll/paste), unsupported sequences degrade safely.

9) AI-critical behaviors
- Stable prompt readiness, predictable copy/paste latency, preserved scrollback/cursor/color state.

10) Scrollback policy
- Default hard cap: 50_000 lines.
- Additional bounded-memory guardrail: high byte budget (default 512 MiB) with oldest-line eviction when exceeded.

11) Window scope
- Single-window baseline in v1.0.

12) Settings UX
- In-terminal command palette is primary (`Ctrl/Cmd + Shift + P`).

13) GPU backend policy
- `wgpu` as graphics backend; platform backends selected by runtime.

14) Visual effects policy
- No expensive effects in v1.0 baseline.

15) Windows scope
- Architecture skeleton only; no full parity claim in v1.0.

16) Observability
- Structured logs, event correlation IDs, runtime diagnostics, optional debug mode.

17) Release metrics baseline
- startup readiness, prompt-to-paint p95, copy/paste p95, frame time, CPU/GPU load, crash-free runtime share, memory growth trend.

18) Distribution
- Manual release flow via GitHub releases + install script.

19) Performance modes
- `cpu`, `gpu`, `auto`.

20) Blocking bugs
- shell start failures, crash loops, severe prompt/color/scroll regressions, leaks, unstable GPU path without safe degrade.

21) Post-v1 features
- multiplexer/multi-window/advanced effects/extended diagnostics are post-v1 roadmap only.

22) Governance
- v1.0 uses manual validation and release docs (no CI gate baseline).

## Self-Authored-First Lock
- Performance-critical runtime logic must be project-owned by default.
- External crates are allowed primarily at integration boundaries (PTY/window/GPU/clipboard/CLI parsing) with explicit contracts.
- Importing third-party terminal-core engines is prohibited in v1.0.
