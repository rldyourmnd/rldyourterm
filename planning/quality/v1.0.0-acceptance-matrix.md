# v1.0.0 Acceptance Matrix (governance sync)

Defined requirement scope: `R-01..R-14` from `planning/system/traceability-matrix-v1.0.0.md`.

Machine-readable release evidence anchor:
- `planning/operations/v1.0.0-evidence-manifest.json`

## Stability

- Req: `R-01`, `R-02`, `R-09`
- Criteria:
  - recoverable GPU/PTY failures do not drop active shell session,
  - fallback behavior is deterministic and bounded,
  - no silent degrade path.
- Evidence:
  - `planning/operations/v1.0.0-manual-test-plan.md`,
  - `bash scripts/ci/run_e2e_governance.sh --mode release`.

## AI CLI Compatibility

- Req: `R-07`, `R-10`, `R-13`
- Criteria:
  - stable long-running behavior for Claude/Codex/Gemini workloads,
  - deterministic startup and prompt readiness,
  - stable copy/paste and output behavior in sustained sessions.
- Evidence:
  - `bash scripts/mvp/run_matrix.sh 3`,
  - manifest artifact markers (`MVP_GATE_RESULT ... status=pass`, `MVP_MATRIX_RESULT ... status=pass`).

## Speed and Latency

- Req: `R-03`, `R-04`, `R-08`
- Criteria:
  - monitor-driven cadence is active,
  - monitor transfer re-sync works without session restart,
  - memory growth is bounded in long-run stress.
- Evidence:
  - pacing scenarios from `planning/operations/v1.0.0-manual-test-plan.md`,
  - manifest profile artifacts for cadence and fallback markers.

## UX and Scope

- Req: `R-05`, `R-11`, `R-12`
- Criteria:
  - settings changes are available via command palette,
  - single-window baseline is enforced and observable,
  - release governance remains manual-only.
- Evidence:
  - `planning/settings/settings_palette.md`,
  - `planning/operations/v1.0.0-release-pack.md`,
  - strict manifest validation markers.

## Architecture and Dependency Governance

- Req: `R-06`, `R-14`
- Criteria:
  - VSA dependency flow remains enforceable,
  - `foundation` integrations are consumed through explicit API contracts/adapters,
  - self-authored-first policy remains enforced.
- Evidence:
  - `bash scripts/ci/validate_vsa_dependency_graph.sh`,
  - `planning/system/dependency-evidence-context7-v1.0.0.md`.

## Evidence Freshness Governance

- Criteria:
  - dated "current run" assertions are not used as authoritative status without manifest anchor,
  - strict freshness checks compare `repo.head_sha` with current `HEAD`,
  - required artifact marker checks pass from manifest contract.
- Evidence:
  - `python3 scripts/ci/refresh_release_evidence_manifest.py`,
  - `bash scripts/ci/validate_release_evidence_freshness.sh --mode policy`,
  - `bash scripts/ci/validate_release_evidence_freshness.sh --mode strict`.
