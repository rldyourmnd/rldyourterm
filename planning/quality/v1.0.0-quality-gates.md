# v1.0.0 Quality Gates (governance sync)

Priority order is fixed and release-blocking: `Stability -> AI CLI Compatibility -> Speed/Latency`.
Defined requirement scope: `R-01..R-14`.

Machine-readable release evidence anchor:
- `planning/operations/v1.0.0-evidence-manifest.json`

## Gate Group A: Stability (Must Pass)

- Req: `R-01`, `R-02`, `R-09`
- Shell session continuity is preserved through recoverable GPU/PTY faults.
- `auto` mode applies bounded retry + deterministic `gpu -> cpu` fallback.
- No silent fallback: every transition is observable and user-visible.
- PTY->GUI output ingestion remains bounded.
- No known crash/panic path in required scenarios.

## Gate Group B: AI CLI Compatibility (Must Pass)

- Req: `R-07`, `R-10`, `R-13`
- Long-running sessions work reliably for `Claude Code`, `Codex`, `Gemini CLI`.
- Prompt readiness remains deterministic after startup and fallback events.
- Copy/paste and output behavior remain stable in prolonged sessions.

## Gate Group C: Speed and Latency (Must Pass)

- Req: `R-03`, `R-04`, `R-08`
- Monitor-driven frame cadence is active in the primary runtime path.
- Monitor transfer cadence re-sync is preserved.
- CPU/RAM growth remains bounded for long-run scenarios.
- Scrollback keeps dual bounds (`50_000` lines + `512 MiB` byte budget default).

## Gate Group D: UX and Scope (Must Pass)

- Req: `R-05`, `R-11`, `R-12`
- Settings are primarily applied via in-terminal command palette.
- Single-window baseline is preserved.
- Release governance remains manual-only for v1.0.0.

## Gate Group E: Architecture and Dependency Governance (Must Pass)

- Req: `R-06`, `R-14`
- VSA boundary contracts remain enforceable.
- `foundation` integrations are consumed through explicit API traits/adapters.
- Dependency direction checks run via `bash scripts/ci/validate_vsa_dependency_graph.sh`.

## Gate Group F: Evidence Freshness Governance (Must Pass For Release)

- HEAD-bound policy is defined in `planning/operations/v1.0.0-evidence-manifest.json`.
- Strict evidence artifacts must carry explicit provenance marker `repo_head_sha=<selected HEAD>`.
- Manifest refresh commands:
  - in-place baseline update: `python3 scripts/ci/refresh_release_evidence_manifest.py`
  - preferred clean-worktree preview for strict release validation: `python3 scripts/ci/refresh_release_evidence_manifest.py --output /tmp/rldyourterm-evidence-manifest.json`
- Policy contract validation:
  - `bash scripts/ci/validate_release_evidence_freshness.sh --mode policy`
- Release strict validation:
  - `bash scripts/ci/validate_release_evidence_freshness.sh --manifest /tmp/rldyourterm-evidence-manifest.json --mode strict`
- Aggregated governance entrypoint:
  - `bash scripts/ci/run_e2e_governance.sh --mode ci`
  - `bash scripts/ci/run_e2e_governance.sh --mode release --manifest /tmp/rldyourterm-evidence-manifest.json`
  - if generating fresh compatibility artifacts in the same flow: `bash scripts/ci/run_e2e_governance.sh --mode release --manifest /tmp/rldyourterm-evidence-manifest.json --with-matrix` (matrix first, manifest refresh second, strict validation third)
