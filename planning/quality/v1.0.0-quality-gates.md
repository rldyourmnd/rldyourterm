# v1.0.0 Quality Gates (reset sync)

Priority order is fixed and release-blocking: `Stability -> AI CLI Compatibility -> Speed/Latency`.
Defined requirement scope for gates: `R-01`..`R-14`.

## Gate Group A: Stability (Must Pass)

- Req: `R-01`, `R-02`, `R-09`
- Shell session continuity is preserved through recoverable GPU/PTY faults.
- `auto` mode applies bounded retry + deterministic `gpu -> cpu` fallback.
- No silent fallback: every transition is observable and user-visible.
- No known crash/panic path in required scenarios.

## Gate Group B: AI CLI Compatibility (Must Pass)

- Req: `R-07`, `R-10`, `R-13`
- Long-running sessions work reliably for:
  - `Claude Code`
  - `Codex`
  - `Gemini CLI`
- Prompt readiness remains deterministic after startup and after fallback events.
- Copy/paste and output behavior remain stable during prolonged use.

## Gate Group C: Speed and Latency (Must Pass)

- Req: `R-03`, `R-04`, `R-08`
- Prompt-to-paint latency remains within manual target envelope for target platforms.
- Copy/paste latency remains within manual target envelope.
- CPU/RAM growth remains bounded in long-run manual stress.
- Frame pacing follows monitor-driven cadence; no hardcoded fps target in primary path.

## Gate Group D: UX and Scope (Must Pass)

- Req: `R-05`, `R-11`, `R-12`
- Settings are primarily applied via in-terminal command palette.
- Single-window baseline is preserved.
- Scrollback default cap remains 50_000 lines.
- Release governance remains manual-only for v1.0.0.

## Gate Group E: Architecture and Dependency Governance (Must Pass)

- Req: `R-06`, `R-14`
- VSA boundary contracts remain enforceable, with inward dependency flow preserved.
- `foundation` integrations are consumed through explicit API traits/adapters only.
- Self-authored-first runtime policy is preserved; dependency usage stays boundary-limited with explicit contracts and evidence.
